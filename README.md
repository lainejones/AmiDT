# AmiDT - fast, small picture datatypes for AmigaOS 3.x

Datatypes let MultiView, AmiFM's View and every other datatypes program show
pictures. AmiDT's are written to be quick on a plain 68020/68030 and to keep
memory use low. They also work on AmigaOS 3.0 and 3.1, which have no PNG, GIF
or BMP support at all.

| Format | Class | Size | What it reads |
|---|---|---|---|
| PNG | `png.datatype` | 12 KB | every colour type and bit depth, interlaced (Adam7) |
| GIF | `gif.datatype` | 7 KB | 87a/89a, interlaced, the first image of an animation |
| BMP | `bmp.datatype` | 9 KB | 1/4/8-bit (plain, RLE4, RLE8), 16/24/32-bit (plain + BITFIELDS), OS/2 |
| TGA | `tga.datatype` | 7 KB | colour-mapped, true colour, grey; plain or RLE; any origin |
| PCX | `pcx.datatype` | 8 KB | mono, 16 colours (EGA), 2/4-bit, 256 colours, 24/32-bit |
| ICO | `ico.datatype` | 16 KB | Windows icons: the biggest image, BMP or PNG inside |
| QOI | `qoi.datatype` | 6 KB | "Quite OK Image" pictures |

## Why they're fast

Most of the time an AGA Amiga spends on a true colour picture is not decoding
it: OS 3.2's picture.datatype then spends seconds turning 24-bit pixels into
the screen's 256 colours. AmiDT's classes make the 8-bit picture themselves
while they decode, row by row - a fixed 6x7x6 colour cube with a 4x4 ordered
dither, three table lookups a pixel - and hand picture.datatype a finished
8-bit planar bitmap (V40 style, which is also what OS 3.0/3.1 understand).

A1200, 68030 at 50 MHz, 640x480, opening the picture as MultiView does:

|                  | AmiDT           | AmigaOS 3.2      |
|---|---|---|
| PNG true colour  | 5.3 s,   32 KB  | 17.5 s, 1207 KB  |
| PNG 256 colours  | 1.8 s           | 3.7 s            |
| PNG 1-bit        | 0.3 s           | 2.2 s            |
| BMP true colour  | 1.5 s,   30 KB  | 12.0 s, 1213 KB  |
| GIF 256 colours  | 3.0 s           | 4.7 s            |
| TGA true colour  | 1.5 s           | (can't open)     |

The trade-off: true colour is always reduced to 256 colours. On a graphics
card (RTG) screen the system's own PNG datatype can show it in full colour, so
the installer keeps the system's PNG, GIF and BMP datatypes on machines that
display on a graphics card.

## Requirements

AmigaOS 3.0 or newer and a 68020 or better.

## Install

1. Unpack `AmiDT-<version>.lha`.
2. Double-click **Install_AmiDT**. Choose the parts:
   - **New formats** (TGA, PCX, ICO, QOI): adds their datatypes and their
     `DEVS:DataTypes` descriptors. Nothing on the system is replaced.
   - **PNG, GIF and BMP**: on AmigaOS 3.0/3.1 this adds them (with their
     descriptors). On 3.2 it replaces the system's classes - unless the Amiga
     displays on a graphics card (the installer asks when Picasso96 or
     CyberGraphX is installed), where AmiDT's are only added where the system
     has none.
3. Reboot once if PNG, GIF or BMP were replaced (the old classes may still be
   in memory). The new formats work straight away.

The system's originals are kept in `SYS:Classes/DataTypes/AmiDT-Originals`.
Run the installer again and choose **Remove** to put them back.

By hand: copy the classes from `Classes/DataTypes` to `SYS:Classes/DataTypes`
and the descriptors you need from `DEVS/DataTypes` to `DEVS:DataTypes`, then
run `AddDataTypes REFRESH`.

**JPEG:** AmiDT has no JPEG datatype; JFIFdt44 (Aminet `gfx/show/JFIFdt44.lha`)
is the fast one. With it installed, run Install_AmiDT again: it sets JFIFdt44
to its fast 256-colour mode (`ENVARC:classes/datatypes/jfif44.prefs` =
`V42MODE DITHER=ORDERED`) - 4.7 s instead of 14.4 s for a 640x480 JPEG on the
A1200 above.

## Building

Needs bebbo's amiga-gcc (m68k-amigaos-gcc) and Python 3; build under Linux/WSL:

```
make all                 # out/<fmt>.datatype, out/DataTypes/<NAME>, out/dtbench
make bench               # the same classes as amidt<fmt>.datatype, for benchmarks
python3 tools/mkpkg.py   # out/release/AmiDT - the installer package
```

- `src/core/` - the decoders, plain portable C: inflate, PNG, GIF, BMP, TGA, PCX,
  ICO, QOI, and the quantiser. They hand out finished 8-bit rows.
- `src/dt/` - the datatype side: the library and its ROM tag, the class
  dispatcher, the chunky-to-planar writer. One small file per format
  (generated by `tools/mkclasses.py`, which also writes the descriptors).
- `src/dtbench.c` - `dtbench FILE/M [REPEAT/N] [LAYOUT/S] [CLASS/K] [DUMP/K]`:
  times how long a datatype takes to open a file; `CLASS=` loads a class from a
  file instead of the installed one, `DUMP=` writes the picture it made.

### Tests

`test/host_png.c` builds the same cores on a PC: `make test/host_png`, then
`python3 test/make_corpus.py` (writes test/corpus: about 150 GIF/BMP/TGA/PCX/ICO/QOI
variants) and `python3 test/check_png.py` (PngSuite + the corpus, pixel by
pixel against Pillow; a few files carry their own reference where Pillow reads
them wrongly or not at all). `sh test/fuzz.sh N` decodes mutated files under
AddressSanitizer. `tools/amicheck.py` checks that a class on a real Amiga (over
NetHarness) makes exactly the same picture as the PC build.
